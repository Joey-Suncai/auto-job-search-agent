# Resume Updater

Every sentence on a resume traces to a confirmed fact; Claude writes a direction's master **once**, Joey approves it,
and per job the scripts only change it mechanically. Rewritten 2026-11-09 around the framework (spec
`docs/specs/materials-resume-framework.md`, ADR-0010); the old role versions are retired, §6.

**Where things are** (code in this skill, data in the data home `~/JobAgent/data`, found via `config/paths.py`):
| What | Path |
| --- | --- |
| Facts (layer ①) | data home `config/facts.json` (fictional twin `config/facts.example.json`) |
| Role library (②) | `<data home>/data/roles/<direction>.json` (generated by `role_library.py`; readers fall back to the code's `roles/`) · `roles/lexicon.json` + `roles/directions.json` (edited by hand) |
| Direction masters (③) | data home `resume/<YYYY-MM>/master_<direction>.json/.md` + `<Prefix>_Resume_<DIR>_Master_A-Classic.docx/.pdf` |
| Per-job output (④) | data home `applications/<date>_<Company>/` — `keyword_map.md`, `tailored.json`, resume docx/pdf, `resume_report.md` |
| Approved wording | `skills/_shared/bullet-bank.md` (master bullets with fact ids + legacy bullets) |
| Prose facts / stories | `skills/_shared/candidate-profile.md`, `story-bank.md`; decisions `decisions-log.md` |
| Layout | `ds_materials.build_docx` (A-Classic, used by ③ ④) · `build_a.py` + TEMPLATE (first master of a new direction by hand only, §7) |

Python: layout, docx and Claude calls need `~/.job-agent-venv/bin/python`; tests run on `python3`.

## 1. Hard rules (every resume, every layer)
1. **Truth only.** Every sentence cites `fact_ids`; every number is a cited fact's *current* number; no never-phrase;
   fact `pairs` hold together ("70%" needs "workflow"). A fact changes only with Joey's yes, logged in `decisions-log.md`.
2. **New wording needs Joey's yes** — written in a session or by `direction_master.py`, approved into a master, then into
   `bullet-bank.md`. Per-job tailoring never writes a sentence.
3. **A gap is asked, never filled.** A fact missing S / T / A / R, a concrete method (dimensions, counts, tool) or a
   number → ask Joey (AskUserQuestion); his answer goes into the fact, or the fact gets `bullet_ok: false`.
4. **Decided — don't re-ask:**
   - Contact: <candidate e-mail> · linkedin.com/in/<handle> · github.com/<user>. Visa status never on a resume.
   - Stock project: team of 3, **"led the code"** (never "led most of the code", "independently", "solo"; Joey 2026-11-09).
   - Job Searching Agent: *(Personal project, built with Claude Code)*, "Ongoing", first project; "designed / operate /
     specified / set", never "coded". Its counts come from fact `jsa.outcome` (337 applications in 15 days, 2026-11-09).
   - Off the resume: XJTLU, NC tax project, the old AI Job-Intelligence Pipeline, U-stage Voice Club (`on_resume: false`,
     Joey 2026-11-08), spoken languages as a skills line.
   - Equity screen: AI tools only gathered the fundamentals data; shortlist 30 stocks. LCOF model co-built with a consultant.
   - Titles "… Intern". A-Classic is the only visual style.
5. **Bullet rules** (`check_bullets.py`, Joey 2026-11-08 / 11-09, from the peer resume he studied):
   - the first word is an action verb — never "To …, ", "When …, ", "Because …, " first;
   - no causal clause — "because", "since" (not a date), "due to", "owing to"; say the purpose (" to …", "so …") or the result;
   - with a number: what was done + why + impact; without: the problem + how it was solved;
   - **outcome first**: each entry's first bullet states what the whole experience achieved, quantified; later bullets are
     problem → action → effect;
   - name the concrete method (e.g. the 5 rubric dimensions, ChatGPT prompts, a 0–5 score per dimension);
   - ≥ 3 sentence shapes (semicolon / participle / purpose / plain), none on > 40 % of bullets; a verb opens ≤ 2 bullets;
     ≤ 230 characters; ≤ 5 bullets per entry; ≤ 2 bold terms per bullet (a cited fact's skill or a direction keyword);
   - plain words — banned: leverage(d), spearhead(ed), orchestrate(d), synergy, dynamic, passionate, results-driven,
     cutting-edge, detail-oriented, team player, utilize(d), seamlessly, robust (`check_resume.py` list).
6. **One full page that stays readable** (Rule 6, 2026-10-24): margins ≥ 0.5 in, font ≥ 10 pt, every bullet ≤ 2 lines,
   no one-word last line, `fill.py` bottom 730–756, `check_resume.py` passes. Fit by spacing → font → reserve bullet /
   dropping the bullet worth least to the direction — never a core bullet (an entry's first, or marked `"core": true`), never shrink below the limits.
7. **ATS-safe**: single column, standard section names, no tables / header-footer text / graphics.

## 2. ① Fact base — `facts.json`
Entries (job / project / school / club) and atomic STAR facts: `S T A R`, `numbers` (each appears in S/T/A/R), `skills`,
`anchors` (words that identify the fact in a sentence), `ownership`, `must_keep`, `never`, `pairs`, `resume_ok`,
`bullet_ok`, `history` (old numbers kept when a count is updated), `source`.
- `python3 scripts/facts_check.py [--map]` — schema, number drift, every bank bullet maps to a fact. Exit 1 = fix.
- A fact's `skills` decide what the resume may *claim* (skills lines, headline terms, "true" in a keyword map) — tag a
  skill only when the fact really shows it; a loose tag (e.g. "stakeholder needs") is a claim Joey must confirm.

## 3. ② Role library — `roles/<direction>.json`
`python3 scripts/role_library.py --all [--discover]` (monthly) from the cached JDs: competency weights, keyword groups
with synonyms, section order, headline pattern, angles. Edit `roles/lexicon.json` (keyword groups; add good
`uncovered_terms`) and `roles/directions.json` (selectors, `template` harvard / jakes).
`python3 scripts/gap_report.py --direction <d> | --all` → `resume/<YYYY-MM>/gap_<d>.md`: per competency the evidence
level, missing asks (a **wording gap** = true fact, JD term not tagged / not phrased; a **real gap**), JD tools in `not_true`.

## 4. ③ Direction master — `direction_master.py` (Joey approves once)
| Direction | Track(s) it serves | Master |
| --- | --- | --- |
| `ai_pm` | Product_Manager | **v7 approved 2026-11-09** (`resume/2026-11/master_ai_pm.json`) |
| `data_analyst` | Data_Analyst | **v1 approved 2026-11-09** (`resume/2026-11/master_data_analyst.json`; core jsa ①–④) |
| `ai_agentic` | AI_Agentic_Engineer | **v1 approved 2026-11-09** (`resume/2026-11/master_ai_agentic.json`; core jsa ①–④) |
| `data_engineer` | Data_Engineer | **v1 approved 2026-11-10** (`resume/2026-11/master_data_engineer.json`; core jsa ①–④; Joey 11-10 reversed the 11-09 "not planned") |

Steps for a new or changed master:
1. `--star-gaps` → ask Joey about every fact missing S / T / A / R or a concrete method (exit 4 = questions).
2. Summary: ask once per direction → `--summary yes|no` (stored in `config/profile.json → resume.summary`).
3. Write: `~/.job-agent-venv/bin/python scripts/direction_master.py --direction <d>` (Claude claude-opus-5-5, Keychain
   `jobagent-anthropic`; one retry with the problems, else `.rejected`). No API credit → `--prompt-out p.txt`, write the
   JSON in the session, `--draft master.json` (same checks + layout).
4. Checks inside: fact ids of its own entry, current numbers, never-phrases, pairs, STAR complete, skills only true,
   bold terms, summary, and every rule of §1.5. Layout via `ds_materials.build_docx`; 2–3 **reserve** bullets kept for
   filling and for tailoring.
5. Show Joey the PDF + `master_<d>.md` (bullets with fact ids, keyword coverage vs. the role version). Iterate on his
   feedback (a new rule → `check_bullets.py` / the writer prompt, with DeepSeek cases).
6. **Core bullets** (Joey 2026-11-09 「一定要放的」): the bullets that say what the experience is and what it achieved
   are marked core and never leave the page — not swapped for a reserve bullet, not dropped by the layout (the first
   bullet of every entry is core anyway). Ask Joey which; set with `direction_master.py --direction <d> --core
   "jsa:0,1,2,4"` (0-based, re-lays the master out and, like `--rebuild`, resets `approved`). The other bullets are the flexible slots per JD. AI PM: jsa ①②③⑤; DA, AI Agentic and DE: jsa ①–④.
7. **Approve**: set `approved = {by, date, quote, version}` in `master_<d>.json` (`--rebuild` resets it to null — set it
   again, with an `amended` note), copy the bullets with fact ids and bold terms into `bullet-bank.md`, log it in
   `decisions-log.md`. Only an approved master is used for jobs.

## 5. ④ Per-job tailoring + ⑤ checks (automatic in `ds_materials.py`)
`ds_materials.py --tailor auto` (default) maps the job's track to a direction; **with an approved master** it runs
`tailor.run`, otherwise the master unchanged — never the retired role versions (§6). By hand:
`~/.job-agent-venv/bin/python scripts/tailor.py --jd applications/<folder>/jd.md --direction ai_pm [--out …] [--dry]`.

**④ `tailor.py` — mechanical changes only:**
1. Top 12 JD terms (lexicon clusters; score = competency weight × min(hits, 3) × 2 when in the job title).
2. Truth per term: a resume fact's skill or `skills.true` → true · `skills.not_true` → not used · else not true.
3. Swap to the JD's spelling only between same-number variants (case, hyphens, acronym ↔ expansion; never
   "workflow" → "workflows").
4. Add a JD term to a skills line only when it is itself a true skill (the group holding its evidence facts' skills).
5. Take a reserve bullet (into a non-core slot only) only when it brings a missing JD term, or the JD's spelling of a term the page says another
   way, without losing any term or JD spelling (the lowest-weight later bullet goes; never an entry's first).
6. Order: core bullets first in their approved order, then the other bullets and the skills items by JD terms; `truth_check` reports `core_dropped` when a core bullet is missing.
7. Headline = the exact job title + ≤ 3 true JD terms.

**⑤ `truth_check.py`** — `--tailored T --approved M`: every master check + nothing but mechanical change
(`new_sentence`, `swap_not_variant`, `entry_moved`, `fact_ids_changed`, `summary_changed`, `headline_term`,
`skill_added_untrue`). `--text cover.txt --jd jd.md`: numbers, never-phrases, fact pairs, banned words in prose —
`ds_materials.py` runs it on every cover letter and form answer (`overclaims` → DeepSeek rewrites).
Then layout: one page, bottom 730–756, `check_resume.py`. **Any failure → the approved master unchanged** (never a
weaker resume silently), the reason in `resume_report.md`.

**Output in the application folder:** `keyword_map.md` (weights, coverage before / after, gaps **true but not phrased**
and **not true**, the change list) · `tailored.json` · `<Prefix>_Resume_<Company_Title>_A-Classic.docx/.pdf` ·
`resume_report.md` ("Resume source" section). Report to Joey in Chinese: coverage, gaps, every change.

**Gaps:** "not true" terms are never added. "True but not phrased" terms can only reach the page as new approved
wording — collected per direction, never asked per job inside a batch (§5a).

### 5a. Wording gaps → reserve bullets (`gap_reserve.py`, JSA-262; first run AI PM 2026-11-09)
1. `python3 scripts/gap_reserve.py --direction <d>` → data home `resume/<YYYY-MM>/gap_reserve_<d>.md/.json`: over all the
   direction's JDs (role library `jd_ids`), the true top-12 JD terms the master's page (bullets, skills, headline, entry
   headings) does not say in the JD's spelling — JDs, share, summed score, JD spellings, state (`missing` /
   `other_spelling`) and the exact fact-skill **tags** that make each term "true".
2. **Ask Joey whether each top term's tags are true** (AskUserQuestion). A denied tag:
   `--deny <term> --fact <id>` (or `--fact skills.true`) removes it from the fact; log his answer in `decisions-log.md`.
   (2026-11-09: "stakeholders" denied on hp.rubric and jsa.dash → no longer true; "communication skills" kept on fs.decks.)
3. Joey picks the terms to write. Claude writes 1–2 reserve bullets per term from the cited facts only
   (`--prompt-out p.txt` gives the facts, existing bullets and rules; the API is optional): JSON list of
   `{entry_id, text, fact_ids, bold, gap}`.
4. `--check cands.json`: entry on the master, text new, holds its gap term, `check_bullets.check_bullet` (§1.5) and
   `direction_master.check` with the candidates as the reserve. Show Joey the exact texts.
5. On his yes: `--approve cands.json --quote "<his words>"` → appended to the master's `reserve` (noted under
   `approved.reserve_added`) and to `bullet-bank.md` under the entry's heading. From then on `tailor.py` swaps one in per
   job when it brings a missing JD term **or the JD's own spelling of a term the page says another way** (e.g.
   "trade-offs" vs. "prioritized"), without losing any term or JD spelling (§5 ④.5).
Rerun after each master change or role-library rebuild (monthly).

### 5b. Base track by rules, a score per folder, the daily skill-gap list (JSA-194)
- **Base track** = `pick_track.py` (rules: the job title names the function, else JD keywords with a clear margin); DeepSeek is asked only when the rules are not confident. Headline = `<exact job title> · ≤ 3 true JD terms` (tailor.py, rule-based; the legacy bank-pick path still lets DeepSeek write its headline title). The folder records who chose the track (`track_by` in ds_status.json and materials_score.json). Cases: `scripts/test_pick_track.py`.
- **`materials_score.json`** in every application folder (`scripts/store/materials_score.py`, written by `ds_materials.py`; `--all` backfills): JD-term coverage before / after, base track and direction, bullet fact ids, letter checks (fact check as recorded by the build, banned phrases, words), flags, score 0–100. Advice only — it blocks nothing. Cases: `scripts/test_materials_score.py`.
- **Skill-gap list** (`scripts/store/skill_gap.py`, one row of kind `skill-gap` in Joey's to-do): JD terms no fact shows ("not true" in tailored.json) that recur in ≥ 3 folders from ≥ 2 companies in the last 14 days. It only asks Joey whether he really did any of them; nothing is added to a resume without a confirmed fact. Cases: `scripts/test_skill_gap.py`.

### 5c. Simulated recruiter (`recruiter_review.py`, JSA-252)
`python3 recruiter_review.py --direction ai_pm` (or `--all`): DeepSeek, as a recruiter for the direction's role, scores every bullet and the whole page 1–5 with one reason each plus ≤ 5 "topics to confirm" → `resume/<YYYY-MM>/recruiter_<direction>.{json,md}` next to the master, so Joey sees it when he approves or revises a master. **Advice only:** it blocks nothing, is not run per JD, never edits a master, and its advice is topics to confirm with Joey — not sentences and not facts. Only headline / summary / skills / bullets are sent. Cases: `scripts/test_recruiter_review.py`.

## 6. Retired: the four old role versions (JSA-388, Joey 2026-11-17)
The bank-pick resume built from the four old role versions in `content.py` (`resume/<YYYY-MM>/<Role>_A-Classic.docx`) is retired: with the
Leadership section off (JSA-255) it reached only ~85 % of the page and would have needed new sentences or a larger font — neither is allowed.
`ds_materials.py` now **always** builds the resume from the approved direction master of the track: tailored by `tailor.py`, or the master
unchanged when a tailoring check fails or with `--tailor legacy` (kept as the name of "no tailoring"). No approved master for the track, or a
master that does not lay out → the folder fails at step `tailor` with the reason and is queued — never a bank pick, never an added sentence,
never a font change. The old files stay in the data home (nothing deleted); the code simply never selects them. The DeepSeek step A (bank
bullet selection) still runs for the keyword map / fit map / letter stories, and its keyword map is kept as `keyword_map_legacy.md`.
`build_a.py` and the old template stay for building a NEW direction's first master by hand only (§7).

## 7. A-Classic build internals (`build_a.py`, legacy role versions and the original)
- `python3 scripts/prepare_template.py` unpacks `resume/<First>_<Last>_Resume_UChicago_ADS_original_TEMPLATE.docx` into
  `<data home>/data/work/resume/un/` (JSA-377: never into the code dir — the release is read-only) and merges runs (**never overwrite the template**); `python3 scripts/build_a.py` rebuilds the role versions into `<data home>/data/work/resume/out/` (`paths.work()`)
  (knobs `a_sz`, `a_bullet_after`, `a_section_before`, `skills_a` in `content.py`).
- Paragraph templates: p0 name · p1 contact (+ italic headline) · p2 section header · p3 school · p7 degree · p8 Courses ·
  p13 skill line · p16 org · p17 title + date · p18 bullet (`a4`, numId 2) · p25 project line. `fill(tpl, texts)` replaces
  each `<w:t>` in order; body margins top / bottom 720.
- The **original** `resume/<First>_<Last>_Resume_UChicago_ADS_original.docx` changes only when Joey asks: edit its XML the
  same way, preview first.
- `build_b.js` = retired B-Modern style, don't use.

## 8. Deliver
Preview first — Joey approves every master and every change to the original or role versions. Then archive old files
(`mv`), save the new docx + pdf, update `bullet-bank.md` / facts if wording changed, log in the session log and
`decisions-log.md`.

## 9. Tests (rule 13: DeepSeek writes the cases, Claude judges)
`scripts/test_facts_check.py` · `test_role_library.py` · `test_gap_report.py` · `test_check_bullets.py` (bullet rules +
master check) · `test_tailor.py` (tailor + alternates + truth_check) · `test_gap_reserve.py`; cases in `scripts/test_cases/<name>_cases.json`, judged
